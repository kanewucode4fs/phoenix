# 部署与分发指南

适用版本：Phoenix `20.23.0`。平台运行、SDK 构建和插件分发统一在本页说明。

## 1. 平台部署

<a id="local-source-pg"></a>

### 当前环境

| 项目 | 配置 |
|---|---|
| Phoenix | `http://localhost:6006`；OTLP gRPC：`localhost:4317` |
| 源码镜像／容器 | `phoenix-source:local`／`phoenix-source` |
| PostgreSQL | Mac 上的 `127.0.0.1:5432/phoenix`，版本 `18.6` |
| 容器连接数据库 | `host.docker.internal:5432/phoenix` |
| 工作目录 | 卷 `phoenix-source-data` 挂载到 `/data`；追踪数据保存在 PG |

本节针对 macOS Docker Desktop。容器内 `127.0.0.1` 指向容器自身，访问 Mac 使用 `host.docker.internal`。当前实例已经运行，以下命令用于新建或重建环境。

### 构建、配置与启动

在仓库根目录构建：

```bash
docker build --progress=plain --tag phoenix-source:local .
```

Dockerfile 会构建当前前后端源码。保留 `LICENSE`、`IP_NOTICE`、`README.md`、`pyproject.toml` 和 `uv.lock` 等构建输入。默认使用缓存，不需要常规添加 `--no-cache`。

在被 Git 忽略的 `.env.phoenix` 中填写数据库配置：

```dotenv
PHOENIX_SQL_DATABASE_URL=postgresql://<your-user>:<your-url-encoded-password>@host.docker.internal:5432/phoenix
```

密码需 URL 编码，真实凭证只放在忽略文件或密钥系统中。本机账号若按已有 PG 规则无需密码，可省略密码部分；不需要为接入 Phoenix 改成无密码认证。

```bash
docker volume create phoenix-source-data
docker run --rm --user 0:0 --entrypoint /usr/bin/python3 \
  --mount source=phoenix-source-data,target=/data \
  phoenix-source:local -c "import os; os.chown('/data', 65532, 65532)"

docker run --detach --name phoenix-source --restart unless-stopped \
  --publish 127.0.0.1:6006:6006 \
  --publish 127.0.0.1:4317:4317 \
  --env-file .env.phoenix \
  --env PHOENIX_WORKING_DIR=/data \
  --env PHOENIX_TELEMETRY_ENABLED=False \
  --mount source=phoenix-source-data,target=/data \
  phoenix-source:local
```

同名容器或端口已占用时不要重复创建。该配置仅供本机使用，未开启 Phoenix 认证。对外部署需配置 `PHOENIX_ENABLE_AUTH=True`、稳定保存的 `PHOENIX_SECRET` 和 HTTPS；HTTPS 下再启用安全 Cookie。完整变量见 [config.py](../../src/phoenix/config.py)。

### 验证与日常维护

```bash
curl --fail http://localhost:6006/healthz
curl --fail http://localhost:6006/readyz
docker logs --tail 100 phoenix-source
```

再用 [LangChain + LangGraph demo](../../examples/langgraph_phoenix_demo/README.md) 发送一条追踪，在项目页确认入库；该示例可直接用 Python 运行，无需真实模型密钥。

```bash
docker stop phoenix-source
docker start phoenix-source
docker restart phoenix-source
```

更新源码后应重新构建镜像、重建应用容器，复用 PG 连接和工作卷；重启旧容器不会加载新代码。升级前备份数据库及 `PHOENIX_SECRET`，保留旧镜像。数据库迁移不兼容时，不能仅靠降级镜像恢复。

当前不使用 SQLite 存储追踪。旧 `phoenix-source-sqlite-backup` 容器已停止，未迁移其中数据。

## 2. SDK 与 CLI 的本地开发、构建

Python 本地环境使用 uv；Node／pnpm 版本以 `.nvmrc` 和 `js/package.json` 为准。工具安装与完整开发流程见 [DEVELOPMENT.md](../../DEVELOPMENT.md)。

### Python SDK

| 包 | 源码目录 | 用途 |
|---|---|---|
| `arize-phoenix-client` | `packages/phoenix-client/` | 数据集、实验、追踪查询及 API 客户端 |
| `arize-phoenix-evals` | `packages/phoenix-evals/` | 评估器与评分执行 |
| `arize-phoenix-otel` | `packages/phoenix-otel/` | OTel 注册与追踪导出配置 |
| `arize-phoenix-sqlean` | `packages/phoenix-sqlean/` | SQLite 原生扩展，独立构建，不属于 uv workspace |

```bash
make install-python
# 构建指定 SDK 的 wheel；其余两个纯 Python SDK 替换目录即可
./scripts/uv.sh build --wheel packages/phoenix-client
# 使用已有 tox 测试环境验证三个 SDK
tox run -e phoenix_client,phoenix_evals,phoenix_otel
```

本地 uv workspace 会引用三个 Python SDK 的源码。独立应用应在自己的 uv 虚拟环境中安装构建产物再验证；测试 Agent 位于 `/Users/kanewu/Documents/TechSet/FirstAgent`。

**当前 Dockerfile 使用 `uv sync --no-sources`，安装锁定的已发布 SDK。修改本地 `packages/` 不会自动进入主服务镜像。**需要先提供可安装版本、更新依赖与锁文件，再重建镜像；使用本地 SDK 的镜像验证需另外调整构建来源。

`phoenix-sqlean` 包含 C 扩展，应沿用发布工作流的多平台 wheel 构建，不套用上述纯 Python SDK 命令。

### TypeScript SDK 与 CLI

`js/packages/` 的公开 npm 包均位于 `@arizeai` scope：`phoenix-client`、`phoenix-evals`、`phoenix-otel`、`phoenix-config`、`phoenix-mcp` 和 `phoenix-cli`。其中 `@arizeai/phoenix-testing` 为私有 workspace 工具，不对外发布。

```bash
make install-node
make build-ts
make test-ts
```

CLI 包提供 `px`、`phoenix-cli`、`pxi`；stdio MCP 来自独立 `@arizeai/phoenix-mcp` 包。修改这些包不会自动更新用户已经安装的 CLI，需安装新构建产物或发布新版本。上述测试入口覆盖整个 JS workspace，非单包测试。

## 3. 发布与插件分发

### 包与镜像

| 产物 | 现有发布入口 |
|---|---|
| Python 主包及 SDK → PyPI | [release.yml](../../.github/workflows/release.yml) 创建版本发布，随后触发 [publish.yaml](../../.github/workflows/publish.yaml)；包名与版本来自根 release-please 配置和 manifest。 |
| TypeScript SDK／CLI／MCP → npm | [typescript-packages-publish.yml](../../.github/workflows/typescript-packages-publish.yml)，使用 Changesets；`js/package.json` 的 `ci:publish` 先构建再发布。 |
| Docker 镜像 | [docker-build-release.yml](../../.github/workflows/docker-build-release.yml)，由 `arize-phoenix-v*` 标签触发多架构发布；本地 `docker build` 只生成本地镜像。 |

Python 正式发布使用 release-please 标签；`publish.yaml` 也支持手动分支预览，产生开发预发布版本。生产依赖不应加入这些预发布版本。

自有分发需配置自己的包名／npm scope、制品仓库、GitHub 环境和发布凭证／信任关系。Fork 不会获得上游 PyPI、npm 或镜像仓库的发布权限；不能把复制工作流视为发布配置已完成。保留 `release-please-config.json`、`.release-please-manifest.json` 和 JS Changesets 配置，直到替换相应流程。

### Agent 插件与技能

| 宿主 | 分发入口 |
|---|---|
| Codex | [plugins/codex/arize-phoenix](../../plugins/codex/arize-phoenix/README.md)：插件清单、MCP 配置和启动脚本；本地安装命令见该 README。 |
| Claude Code | [plugins/claude/arize-phoenix](../../plugins/claude/arize-phoenix/README.md) 与根 `.claude-plugin/marketplace.json`；插件附带 MCP 连接及共享技能。 |
| Cursor | [.cursor-plugin](../../.cursor-plugin/)：插件清单、MCP 与技能路径。 |

插件通过对应宿主安装，连接已部署 Phoenix 的 `/mcp`，不需要再启动一套 Phoenix。CLI／Codex 启动器使用 `PHOENIX_ENDPOINT`；应用追踪 SDK 使用 `PHOENIX_COLLECTOR_ENDPOINT`；启用认证时配置对应的 `PHOENIX_API_KEY`。

分发插件时包含清单引用的脚本和资源，并保证共享技能的软链接能解析到实际内容。根 `skills-lock.json` 用于外部技能更新；服务端 MCP 另有自己的锁文件，两者不能混用。
