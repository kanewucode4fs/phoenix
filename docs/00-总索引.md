# 项目文档总索引

> 本项目按 vault 标准 5 段结构组织文档。每段文档独立维护，由 `dev-delivery-check` 跨段做交付一致性检查：Claude Code 调用 `/dev-delivery-check`；Codex 调用 `$dev-delivery-check`。

## 5 段结构

| 段 | 路径 | 内容 | 何时更新 |
|---|---|---|---|
| 1 | `01-需求文档/需求.md` | what to build（用户视角的功能/验收） | 接到新需求 / 需求迭代 |
| 2 | `02-业务架构/业务架构.md` | business flow / 角色 / 数据流 | 业务流程变更 |
| 3 | `03-技术架构/架构详解.md` | tech stack / 模块 / 依赖关系 | 技术栈/模块拆分调整 |
| 4 | `04-部署文档/部署指南.md` | how to deploy / env 配置 / Docker | 部署方式/依赖变更 |
| 5 | `05-使用手册/使用手册.md` | how to use / 命令行 / UI 操作 | 用户接口变更 |

## SDD 增量产物（独立目录）

| 类型 | 路径 | 内容 |
|---|---|---|
| Spec | `docs/specs/YYYY-MM-DD-<topic>.md` 或 `docs/superpowers/specs/...` | 单次需求 spec |
| Plan | `docs/plans/YYYY-MM-DD-<topic>.md` 或 `docs/superpowers/plans/...` | 单次实施 plan + 任务清单 |

## 交付一致性检查

按交付核验要求调用 `dev-delivery-check`，跨 9 份产物（5 段 reference + spec + plan + code + 项目规则文件）做对账。`dev-eod` 只提示检查，不自动执行。公共约定见 `~/Documents/Obsidian/dev-vault/VAULT.md`，两端完整调用见同一 Vault 的 `resources/日常操作指南.md`。

## 项目阶段

本项目当前阶段在项目根适用规则文件的「项目阶段」段声明（值为 `initialization` 或 `iteration`）：Claude 按其入口读取；Codex 由技能加载器选择有效 `AGENTS.override.md` / `AGENTS.md`，项目根兼容后备 `CLAUDE.md`。该字段影响 `dev-delivery-check` 的 SOT 优先级判断。
